# OneMessage: проверка проекта и первого использования

Обновление после аудита: формат Spotlight удалён из интерфейса и отключён в API. Ниже сохранены исторические выводы аудита; текущие доски, профили и рейтинг используют только размещения на досках. Старые записи базы не удалялись.

Проверено 22 октября 2026 года. Это аудит локального прототипа, а не подтверждение готовности к приёму платежей или независимый пентест.

## Что исправлено

- Публичный API профиля больше не отдаёт email. Убран декоративный знак «верифицирован», который показывался всем пользователям, и показатель «заработано», для которого не было реального расчёта выплат.
- Центральное сообщение, запись демопокупки и рекорды сохраняются одной транзакцией. Ошибка записи откатывает весь набор изменений. Сервер сверяет цену, которую подтвердил пользователь: при изменении цены возвращается конфликт, интерфейс предлагает проверить новую сумму.
- SQLite-соединение и подписчики событий разделяются между API-модулями в рамках одного процесса. Экспорт sql.js больше не оставляет внешние ключи выключенными. Файл базы сохраняется через временный файл и атомарное переименование.
- Отключена публичная инициализация базы с тестовым аккаунтом. Отключённый SSE-клиент больше не может превратить успешно сохранённую публикацию в ошибку запроса.
- История показывает сумму конкретной демопокупки, а не цену следующей замены. Рейтинг учитывает публикации доски и центрального сообщения, не присваивает места людям без публикаций и сортируется прежде всего по числу сообщений.
- Добавлены обработка ошибок и повторная загрузка истории/рейтинга. Устаревшие ответы запросов не должны перезаписывать более свежие данные профиля и центрального сообщения.
- Черновик, тариф и клетка сохраняются в sessionStorage до входа. После входа/регистрации пользователь возвращается к форме. Переадресация ограничена адресами внутри приложения. Ошибки доступа к хранилищу не останавливают авторизацию.
- Прямая ссылка открывает сообщение по его ID, даже если временная клетка уже освобождена и занята снова. Ссылка доступна из диалога и профиля.

## Почему теперь легче начать

Раньше посетитель видел много одинаковых клеток, но должен был сам понять, куда нажать и что написать. Теперь на первом экране есть действие «Explore the board», три коротких шага и кнопка выбора свободной клетки. Форма предлагает необязательные первые строки и показывает предпросмотр текста. На доске есть читаемый список последних публикаций текущей страницы.

Черновик не теряется при входе. После публикации можно открыть сообщение и скопировать ссылку для друга. Это создаёт понятный цикл: написать → показать другому → вернуться к доске. Это продуктовая гипотеза; рост интереса и возвращаемости ещё не измерялся. Реакции, ответы и вымышленные участники не добавлялись.

Названия «Permanent wall» и «Past messages» снабжены объяснениями срока и цены. Деморежим остаётся явным: приложение не утверждает, что пользователь реально заплатил или заработал.

## Зависимости

Next.js обновлён с 13.4.10 до 15.5.28. Применены совместимые исправления npm, обновлены вложенные PostCSS и gRPC. Основание для версии Next: [официальное сообщение от 14 октября](https://nextjs.org/blog/nextjs-security-update-october-14-2026).

После обновлений npm audit сообщает 7 замечаний (5 high, 2 moderate), связанных с Tailwind CSS 3 и его зависимостями. Критических замечаний в отчёте нет. Полного устранения этих замечаний не заявляется: для рекомендуемого npm пути потребуется миграция на Tailwind CSS 4 с отдельной проверкой CSS и вёрстки. `npm audit fix --force` не применялся.

## Проверка

28 автоматических проверок проходят. `npm test` проверяет серверную авторизацию, цены, конфликты, откат публикации, внешние ключи, приватность профиля, историю, рейтинг, постоянные ссылки, черновики и безопасные переадресации. Для операций с данными тесты создают отдельные временные базы; пользовательские сообщения не изменяются.

Сборка Next.js 15 проходит. В браузере проверены выбор клетки, подсказки/предпросмотр, переход ко входу с адресом возврата, восстановление текста без публикации и открытие существующего сообщения по ссылке. Проверен перенос длинного сообщения на экране шириной 375 пикселей. Внешний вход с реальным паролем Firebase не выполнялся; проверка токенов в автоматических тестах использует заглушки SDK.

## Что проверить перед публичным запуском

- Настоящая оплата и подтверждение через webhook, политика возврата при конфликте места. Пока это демо.
- Модерация, жалобы, ограничения частоты публикаций и защита от заполнения доски одним аккаунтом.
- Для нескольких серверных процессов — общая транзакционная база и межпроцессные события. Текущие sql.js и SSE-хаб рассчитаны на один процесс и не решают распределённую конкурентность. Нужны резервные копии.
- Завершить миграцию оставшихся зависимостей и повторить аудит.

## Как проверить интерес на небольшой аудитории

Дать новым посетителям задачу «оставь сообщение и отправь другу» и посмотреть, могут ли они выполнить её без объяснений. Сравнивать долю открывших форму, завершивших публикацию и вернувшихся по ссылке. Сначала устранить места, где люди застревают; только затем экспериментировать с реакциями или ответами. Внешняя аналитика и отправка пользовательских данных в сторонние сервисы в этой работе не подключались.
